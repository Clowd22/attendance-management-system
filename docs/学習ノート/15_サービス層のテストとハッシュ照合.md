## 質問

## 回答の要旨（結論）

サービス層のテストは、リポジトリ層とほぼ同じ構造だが、**`password_hash` に「本物のハッシュ」が必要**な点が決定的に違う。最初 `dummy-hash` のままにして `UnknownHashError` で失敗し、`hash_password("pass123")` に修正して全テストが通った。

## テスト対象（app/services/auth_service.py）

`AuthService.authenticate()` は3段階で判定する。

1. 社員番号で社員を検索 → 無ければ `None`
2. `can_login()`（有効・退職していないか）→ ダメなら `None`
3. `verify_password()` で照合 → 不一致なら `None`

すべて通過したら社員（`Employee`）を返す。

## サービス層テストのポイント（リポジトリ層との違い）

リポジトリ層のテストでは `password_hash="dummy-hash"` で良かったが、**サービス層では実際に照合が通るハッシュ**が必要。

```python
emp = Employee(
    ...
    password_hash=hash_password("pass123"),   # 本物のハッシュ
)
```

これで `verify_password("pass123", emp.password_hash)` が `True` になる。

## つまずき：`UnknownHashError`

最初の実行で3件が失敗：

```
pwdlib.exceptions.UnknownHashError: This hash can't be identified.
... password = 'pass123', hash = 'dummy-hash'
```

- **原因**：`"dummy-hash"` は bcrypt のハッシュ形式（`$2b$12$...`）ではないため、pwdlib が「どのハッシュ方式か識別できない」とエラーを投げた。
- **対処**：`password_hash=hash_password("pass123")` に修正。

### なぜ一部は通っていたか

`authenticate()` の**早い段階で `None` を返す**テストは、`verify_password` に到達しないため、`dummy-hash` でも通っていた。

- 存在しない社員番号 → ステップ1（検索）で `None`
- `is_active=False` → ステップ2（can_login）で `None`

逆に、`verify_password` に到達するテスト（success・wrong_password・retired）だけが落ちていた。

## もう一つの修正：退職テスト

```python
employee.is_retired = True   # ❌ Employee に is_retired 属性は無い
employee.retire_date = date(2026, 1, 1)   # ✅ 過去の日付 → can_login() が False
```

退職判定は `retire_date`（退職日）で行う。`can_login()` が「`retire_date` が過去ならログイン不可」と判定する。
