## 質問

> ステップ７のリポジトリ層を実装した。検証したい。こういうのの検証方法からまず教えて。その上で検証は自分でやるので。

## 回答の要旨（結論）

リポジトリ層は **DB に依存する**ため、「テストデータを DB に投入 → リポジトリで検索 → 結果を見る」という流れで検証する。社員テーブルは外部キー（`department_id`・`work_schedule_id`）を持つため、**先に部署・勤務体系を投入してから社員を入れる**必要がある。

## これまでの層との「検証のしやすさ」の違い

| 層 | 検証の方法 | 準備 |
|----|-----------|------|
| ステップ5（security） | 関数を呼んで結果を見る | 不要 |
| ステップ6（schema） | インスタンスを作る | 不要 |
| ステップ7（repository） | DB にテストデータを入れて検索する | 必要 |

ステップ5・6 は「単純な関数・クラス」なので呼ぶだけで検証できるが、リポジトリ層は DB に依存しているため「検索対象のデータ」が DB に入っていないと検証できない。

## 重要な注意点：外部キー制約

社員（`employees`）の `department_id`・`work_schedule_id` は外部キー。ステップ2 で `PRAGMA foreign_keys=ON` を有効化しているので、存在しない部署ID・勤務体系IDで社員を入れようとするとエラーになる。

→ 検証では**先に部署・勤務体系を投入してから社員を入れる**。

## 検証手順（4段階）

1. セッションを用意（`SessionLocal()`）
2. テストデータ投入（部署・勤務体系 → 社員の順）
3. リポジトリのメソッドを呼ぶ（`get_by_employee_number` / `get_by_id`）
4. 結果を確認（取得できたか、`None` になるか）

## 検証スクリプト（コピペして実行可）

```bash
.venv/bin/python <<'EOF'
from datetime import date, time
from app.db.session import SessionLocal
from app.models.department import Department
from app.models.work_schedule import WorkSchedule
from app.models.employee import Employee
from app.repositories.employee_repository import EmployeeRepository

db = SessionLocal()

# 1) 部署と勤務体系を用意（外部キー制約のため先に必要）
dept = Department(code="TEST", name="テスト部署")
sched = WorkSchedule(
    code="TEST", name="テスト勤務",
    start_time=time(9, 0), end_time=time(18, 0), required_minutes=480,
)
db.add(dept)
db.add(sched)
db.commit()  # id が採番される

# 2) 社員を投入（default がある role/is_active/created_at/updated_at は省略）
emp = Employee(
    employee_number="TEST001",
    last_name="テスト", first_name="太郎",
    last_name_kana="テスト", first_name_kana="タロウ",
    department_id=dept.id,
    employment_type="seishain",
    work_schedule_id=sched.id,
    hire_date=date(2026, 1, 1),
    password_hash="dummy-hash",
)
db.add(emp)
db.commit()

# 3) リポジトリで検証
repo = EmployeeRepository(db)

found = repo.get_by_employee_number("TEST001")
print("社員番号で検索:", found.full_name if found else "None")

found2 = repo.get_by_id(emp.id)
print("IDで検索:", found2.full_name if found2 else "None")

print("存在しない社員番号:", repo.get_by_employee_number("NO_SUCH"))  # None になるはず

# 4) 後片付け（テストデータを消して再実行できるようにする）
db.delete(emp)
db.commit()
db.delete(dept)
db.delete(sched)
db.commit()

db.close()
EOF
```

### 期待される出力

```
社員番号で検索: テスト 太郎
IDで検索: テスト 太郎
存在しない社員番号: None
```

## 見るべきポイント

- `社員番号で検索` と `IDで検索` がどちらも `テスト 太郎`（`full_name`）を返すこと → 検索が正しく動いている
- `存在しない社員番号` が `None` になること → 「見つからない」を正しく扱えている
- 末尾でテストデータを消しているので、何度でも再実行できる
