# コミットとプッシュはどのタイミングでやる？

| 項目 | 内容 |
|------|------|
| 作成日 | 2026-09-03 |
| 種別 | 手順（Git 運用） |

## 質問

> フェーズ0から始めてる。どのタイミングでコミットしたりプッシュすればいいの？

## 回答の要旨（結論）

**1つの「意味のある単位」が完成して動作確認できたらコミットし、コミットしたら基本毎回プッシュする。**

Phase 0 では、詳細設計書の「ステップ」1つがちょうど良いコミット単位になる。

## ポイント

### コミットのタイミング

- 設計書の「ステップ」が1つ完成し、そのステップの「確認」コマンドで**動くことを確かめてから**
- 「動く状態」を保つ（作りかけ・エラーが残ったままをコミットに含めない）
- コミットメッセージは日本語で簡潔に
  - 例: `Phase 0 ステップ2: DB基盤（base.py, session.py）を追加`

### プッシュのタイミング

- コミットしたら毎回でOK。パブリック・自分専用リポジトリでは「**バックアップ**」の意味もある
- 最低でも1日の作業の終わりに push

### ブランチ

- 1人・学習用途なら **main 直push** で統一してOK
- 実務の練習をしたくなったら feature ブランチ（例: `feature/phase0-auth`）を切って main にマージ、を試す
