# テスト設計：正常系・異常系・境界値

| 項目 | 内容 |
|------|------|
| 作成日 | 2026-09-13 |
| 種別 | 概念理解（テスト設計） |

## 質問

> 本来であれば新しくこの従業員登録であったり、様々な機能を追加するたびにこのtestsディレクトリに検証用のコードを書いて実行して検証するということになるわけですね。このとき正常系のみの検証ですか？異常系の検証やテストケースなどは明文化しなくてもよいのでしょうか。本来であればするべきでしょう。

## 回答の要旨（結論）

機能を追加するたびに `tests/` にテストを書いて `pytest` で実行する、という理解で正しい。テストは**正常系だけでなく異常系も**書くべきで、テストケースは**テストコードの `assert` として明文化**される。最低限「正常系＋主要な異常系」を書くのが実務の標準。

## 機能追加とテストの関係

- 機能（層）を追加 → 対応するテストを `tests/` に追加 → `pytest` で実行
- 重要なのが「回帰テスト」：新機能追加時に `pytest` で既存テストも全部実行し、「既存機能が壊れていないか」を確認する。これが自動テスト最大の利点。

## テスト設計の3分類

| 分類 | 目的 | 例（リポジトリ層） |
|------|------|-------------------|
| 正常系 | 正しい入力で正しい結果 | 存在する社員番号 → 社員が返る |
| 異常系 | 不正な入力で安全に処理 | 存在しない社員番号 → `None` |
| 境界値 | 制限の境界で正しく判定 | 20文字ちょうど／21文字（スキーマ層） |

## テストケースの「明文化」とは

テストケースの明文化は、この場合**テストコードの `assert` そのもの**が担う。

```python
def test_get_by_employee_number_not_found(db):
    assert repo.get_by_employee_number("NO_SUCH") is None  # ← 異常系の明文化
```

- 正常系2件（`test_get_by_employee_number`・`test_get_by_id`）
- 異常系1件（`test_..._not_found`）

「見つからないときは `None` を返す」という仕様を、異常系テストとして明文化している。

## さらに追加できる異常系・境界値の例（リポジトリ層）

- 異常系：`get_by_employee_number("")`（空文字）→ `None`
- 境界値：社員番号の上限20文字ちょうど／21文字（スキーマ層 `LoginForm` の役割だが、DB 検索側でも確認できる）

## 実務の標準

「どこまで書くか」はバランスだが、最低限「**正常系＋主要な異常系**」を書く。境界値（上限・下限の前後）も、バリデーションがある場合は書く価値が高い。
