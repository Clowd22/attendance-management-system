# config.pyは結局何をしたいのか？

| 項目 | 内容 |
|------|------|
| 作成日 | 2026-09-03 |

## 質問

> config.pyの解説がほしい。いろいろコメントにも書いてあるけど結局何がしたいの？例えを使ってもいいので解説がほしい。初学者です

## 回答の要旨（結論）

**アプリ全体で使う「環境で変わる設定値」（DBの場所・デバッグON/OFF・秘密鍵など）を、コードにベタ書きせず `.env` から読み込んで、どこからでも同じ1つの設定として参照できるようにする**のが目的。

「**設定をコードから分離する**」考え方が学びの本質。コードのテクニックを覚えるのが目的ではない。

## なぜ必要か（ベタ書きの何が困るか）

| 問題 | 内容 |
|------|------|
| 1 | 本番で値が違う → コードを書き換えなきゃいけない |
| 2 | 秘密鍵がコードに混ざる → GitHub に上げたら情報漏えい |
| 3 | 同じ文字列を何度も書く → 変更時に修正漏れ |

## 例え：レストランの厨房

```
.env（オーナーが差し替える「仕入れリスト」）
   │ read
   ▼
Settings（共通の食品庫）── app_env / debug / secret_key / database_url
   │ どのシェフも同じ食品庫から取る
   ▼
session.py・認証コード など（シェフたち）
```

- **シェフたち**（アプリの各モジュール）＝ 材料（設定値）を共通の食品庫から取る
- **食品庫（Settings）**＝ `.env` の仕入れリストに従って中身が決まる。リストを変えれば全体に反映
- **仕入れリスト（.env）**＝ 値の置き場所。`.gitignore` で除外済みなので秘密鍵も外に漏れない

## コードの各要素の役割

| コード | 役割 |
|--------|------|
| `class Settings(BaseSettings)` | 「環境変数読書マシン」。継承すると `.env` を自動で読む |
| `database_url: str = "sqlite:///..."` など | 設定1つ1つ。型の指定で変換・チェックを自動化。デフォルト値＝ `.env` に無ければ使う初期値（`.env` 優先） |
| `model_config = SettingsConfigDict(...)` | 「どのファイルを読むか」を指定（`.env`、utf-8、未知変数は無視） |
| `get_settings()` + `@lru_cache` | どこからでも同じ設定一式を返す窓口。キャッシュで読み直しの無駄を防止 |

## どう使われるか（次ステップ）

```python
from app.core.config import get_settings
settings = get_settings()
settings.database_url  # DB の場所を取り出して使う
```
