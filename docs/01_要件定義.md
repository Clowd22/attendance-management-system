## 1. はじめに

### 1.1 目的

本システムは、社員の**出退勤の打刻管理**・**勤務時間の集計**・**勤怠データの修正管理**をデジタル化することを目的とする。

紙のタイムカードやExcelでの集計に代わり、以下の実現を目指す。

- 打刻情報を電子的に記録し、改ざんしにくくする
- 勤務時間・残業時間を自動計算し、集計作業の工数を削減する
- 勤怠データの修正に理由と履歴を残し、トレーサビリティ（追跡可能性）を確保する
- 人事・総務担当者が全社の勤怠を一元的に確認できるようにする

### 1.2 背景

- 勤怠管理は労働基準法上の義務であり、正確な記録と保存が求められる
- 従来の紙・Excel運用では、集計ミス・改ざん・データ散在が課題
- 小規模組織（想定100名規模）をターゲットとし、低コストで運用可能なWebアプリケーションとして構築する

### 1.3 本プロジェクトの位置づけ

本プロジェクトは**Webアプリケーション開発の学習を主目的**とする。そのため、以下の方針をとる。

- コードには細かなコメントを記述する
- `docs/` 配下に要件定義・設計書を実務レベルで整備する
- 技術選定は実務で広く使われる構成（FastAPI + SQLAlchemy + SQLite）とする

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| **勤怠** | 出勤・退勤・休憩・外出・休暇などの労働状況のこと |
| **打刻** | 出勤・退勤・休憩開始・休憩終了などを、その時点の時刻を記録して行う操作 |
| **勤務日** | 労働の対象となる日。本システムでは「出勤打刻が行われた日」を基準に判定する（夜勤など0時を跨ぐ勤務も出勤日の所属とする） |
| **所定労働時間** | 就業規則で定められた1日あたりの労働時間（例: 8時間） |
| **実労働時間（実働）** | 実際に労働した時間。`退勤時刻 - 出勤時刻 - 休憩時間` で計算する |
| **残業時間（時間外労働）** | 所定労働時間を超えて労働した時間 |
| **深夜労働** | 22:00〜翌5:00の労働時間（労働基準法上の深夜割増対象） |
| **遅刻** | 所定始業時刻より遅れて出勤すること |
| **早退** | 所定終業時刻より早く退勤すること |
| **欠勤** | 労働すべき日に出勤しなかったこと |
| **休暇** | 就業規則で認められた労働義務のない日（年次有給休暇・慶弔休暇など） |
| **人事マスター** | 社員・部署・勤務体系・休暇種別などの基本データ |
| **デイリーデータ** | 1日単位の勤怠データ（出勤時刻・退勤時刻・休憩時間・勤怠状態など） |
| **マスタ** | システムの基準となる基本データ（マスタデータ） |

## 3. システム概要

### 3.1 システム全体像

```
┌──────────────────────────────────────────────────┐
│                    利用者（ブラウザ）              │
│   一般社員 / 管理者（人事・総務担当）               │
└──────────────────────┬───────────────────────────┘
                       │ HTTP (HTTPS)
┌──────────────────────▼───────────────────────────┐
│             Web アプリケーション                  │
│        FastAPI（Jinja2テンプレートで画面生成）      │
│  ・認証（社員ID/パスワード、セッション）            │
│  ・打刻・勤怠照会・修正・集計の各機能               │
└──────────────────────┬───────────────────────────┘
                       │ SQLAlchemy ORM
┌──────────────────────▼───────────────────────────┐
│                 SQLite データベース               │
│  人事マスタ / 打刻記録 / 日別勤怠 / 集計結果        │
└──────────────────────────────────────────────────┘
```

### 3.2 運用イメージ

- 一般社員は出勤時・退勤時に「打刻」ボタンを押す
- 管理者（人事・総務）は日次・月次で勤怠データを確認・修正し、月次集計結果をCSVで出力する
- 勤怠データは修正履歴とセットで保存され、誰がいつ何を修正したかが追跡できる

## 4. ユーザーとロール

### 4.1 ロール一覧

| ロール | 概要 | 主な権限 |
|--------|------|----------|
| **一般社員** | 全社員が持つ基本ロール | 自分の打刻、自分の勤怠閲覧、自分の修正申請、自分の休暇申請 |

> ※ ロールは1ユーザーに1つ（一般社員 / 管理者）を想定する。システム管理者は要件の初期段階では管理者に含め、ユーザーアカウント管理も管理者権限とする。

|------|:---:|:---:|
| 打刻 | ○ | ○ |
| 自分の勤怠閲覧 | ○ | ○ |
| 全員の勤怠閲覧 | - | ○ |
| デイリーデータ修正 | 申請のみ | 修正・承認 |
| 休暇申請 | 申請のみ | 承認 |

| 月次集計・CSV出力 | - | ○ |

### 5.1 認証・アクセス制御

#### F-01 ログイン

- 社員IDとパスワードでログインする
- ログインに成功するとセッションを発行し、ブラウザのCookieに保存する
- ログイン失敗時は「IDまたはパスワードが誤っています」とだけ表示する（どちらが誤っているかを教えない=情報漏えい防止）
- 未ログイン状態で保護されたページにアクセスした場合は、ログイン画面へリダイレクトする

**[受入条件]**
- 正しいID/パスワードでログインできること
- 誤ったパスワードではログインできないこと

#### F-02 ログアウト

- セッションを破棄してログアウトする

#### F-03 ロールベースのアクセス制御

- 管理者のみがアクセスできる機能（マスタ管理・全員の勤怠閲覧・集計など）には、管理者以外のアクセスを拒否する
- アクセス拒否時は 403（権限なし）ページを表示する

### 5.2 人事マスター管理

> 人事マスターは管理者のみが操作できる。

#### F-04 部署マスタ管理

- 部署コード・部署名・備考を管理する
- 一覧表示・新規登録・編集・削除ができる
- 社員が所属している部署は削除できない（整合性チェック）

**[受入条件]**
- 部署コードは重複登録できない
- 社員が所属中の部署を削除しようとした場合はエラーメッセージを表示する

#### F-05 社員マスタ管理

以下の項目を持つ社員情報を管理する。

| 項目 | 必須 | 説明 |
|------|:---:|------|
| 社員番号 | ○ | ログインIDとしても使用。重複不可 |
| 氏名（姓） | ○ | |
| 氏名（名） | ○ | |
| フリガナ（姓・名） | ○ | 50音順ソート等に使用 |
| 所属部署 | ○ | 部署マスタと関連 |
| 役職 | △ | 任意 |
| 雇用形態 | ○ | 正社員 / 契約社員 / アルバイト 等 |
| 勤務体系 | ○ | 勤務体系マスタと関連（所定労働時間の算出に使用） |
| 入社日 | ○ | |
| 退職日 | △ | 退職日が入るとログイン不可になる |
| メールアドレス | △ | 任意 |
| 備考 | △ | 任意 |

- 一覧表示（検索・絞り込み）、新規登録、編集ができる
- 退職した社員は一覧から「退職」として表示し、削除はせずに残す（勤怠データとの整合性を保つため）

#### F-06 勤務体系マスタ管理

勤務時間帯の基準を管理する。社員の実労働時間・残業計算の基礎となる。

| 項目 | 説明 |
|------|------|
| 勤務体系コード | 重複不可 |
| 勤務体系名 | 例: 標準8時間 / 短時間勤務 / シフト勤務 |
| 所定始業時刻 | 例: 09:00 |
| 所定終業時刻 | 例: 18:00 |
| 所定労働時間 | 例: 8時間00分 |
| 休憩時間 | 例: 1時間00分 |
| 深夜時間の扱い | 22:00〜5:00 を深夜として集計 |

- 一覧表示・新規登録・編集・削除

#### F-07 休暇種別マスタ管理

| 項目 | 説明 |
|------|------|
| 休暇種別コード | 例: PAID / YU-KYU / KEIGA 等 |
| 休暇種別名 | 例: 年次有給休暇 / 慶弔休暇 / 特別休暇 / 欠勤 |
| 付与日数 | 年間付与日数（任意） |
| 繰越可否 | 翌年度への繰越ができるか |
| 半日休暇可否 | 半日単位で取得できるか |

#### F-08 ユーザーアカウント管理

- 社員マスタの登録時にログイン用の初期パスワードを設定する
- パスワードは bcrypt でハッシュ化して保存する（平文保存はしない）
- ロール（一般社員 / 管理者）を割り当てる

### 5.3 打刻機能

#### F-09 出勤打刻

- ログイン済みの社員が出勤時刻を記録する
- 記録する時刻は**サーバーの現在時刻**を使用する（ブラウザ側の時刻を信用しない）
- 出勤打刻が行われた日を「勤務日」とする

#### F-10 退勤打刻

- その日の勤務を終えた時刻を記録する
- 出勤打刻がない状態で退勤打刻はできない（順序チェック）

#### F-11 休憩開始・終了打刻

- 休憩の開始・終了時刻を記録する
- 休憩時間は実労働時間の計算で控除する

#### F-12 外出開始・終了打刻（任意）

- 私用等での外出の開始・終了時刻を記録する
- 外出時間も実労働時間から控除する

#### F-13 打刻履歴の表示

- 対象日の打刻履歴（出勤・休憩・外出・退勤）を時系列で表示する

#### F-14 打刻ルール（業務ルール）

| No | ルール | 内容 |
|----|--------|------|
| R-01 | 二重打刻防止 | 同じ種別（出勤など）を続けて打刻できない。出勤済みの日に再度「出勤」打刻した場合はエラーとする |
| R-02 | 打刻順序チェック | 出勤 → 休憩開始 → 休憩終了 → 退勤 の順序を逸脱した打刻はエラーまたは警告とする |
| R-03 | 深夜0時跨ぎ | 深夜勤務で日付をまたいだ場合も、勤務日は**出勤打刻日**に属するものとする |
| R-04 | 打刻の上書き | 通常の打刻操作では過去の打刻を変更できない（変更は「デイリーデータ修正」で行う） |

> **設計メモ**: 打刻の時刻は「勤務日 + 時刻」で保存する。0時を跨いだ場合、退勤時刻（例 06:00）は前日の勤務日に紐付ける。実装時に `勤務日 + タイムゾーン` の扱いを設計書で明確化する。

### 5.4 勤怠照会

#### F-15 月次カレンダー表示（個人）

- 対象月のカレンダーを表示し、各日に勤怠状態（出勤/休暇/欠勤/休日）を色分け表示する
- 日付をクリックするとその日の勤怠詳細に遷移する

#### F-16 勤怠詳細（日次）表示

- 対象日の以下の情報を表示する
  - 出勤時刻・退勤時刻・休憩時間・外出時間
  - 実労働時間・残業時間・深夜時間
  - 勤怠状態（出勤/遅刻/早退/欠勤/休暇）
  - 打刻履歴

### 5.5 デイリー修正

#### F-17 日次勤怠データの修正

- 打刻忘れ・誤打刻があった場合に、管理者が該当日の勤怠データを修正する
- 修正できる項目: 出勤時刻・退勤時刻・休憩時刻・勤怠状態（遅刻/早退/欠勤/休暇等）
- 修正後は自動で実労働時間等の計算をやり直す
- 本人（一般社員）は修正を**申請**することのみ可能とし、管理者の承認をもって反映する（修正承認フロー）

#### F-18 修正理由の記録・修正履歴の管理

- 修正時に必ず「修正理由」を入力する（必須）
- 修正履歴として「いつ・誰が・何を・なぜ」を記録し、一覧表示できる

**[受入条件]**
- 修正理由を入力せずに修正はできない
- 修正履歴は後から参照でき、遡って書き換えられない

#### F-19 休暇・欠勤の登録

- 休暇日・欠勤日の登録（管理者は直接登録、一般社員は申請）
- 休暇種別（有給・慶弔・欠勤など）と日数を登録する
- 年間の有給休暇の取得日数・残日数を管理する（任意・拡張）

### 5.6 集計機能

#### F-20 月次集計（個人）

対象社員・対象月について以下の項目を集計する。

| 集計項目 | 説明 |
|----------|------|
| 出勤日数 | 出勤（遅刻・早退含む）した日数 |
| 所定労働時間 | 出勤日数 × 1日あたり所定労働時間 |
| 実労働時間 | 出勤日の実労働時間の合計 |
| 残業時間 | 実労働時間 − 所定労働時間（マイナスは0） |
| 深夜労働時間 | 22:00〜5:00 に該当する労働時間の合計 |
| 遅刻回数・時間 | 遅刻した回数と時間の合計 |
| 早退回数・時間 | 早退した回数と時間の合計 |
| 休暇日数 | 種別ごとの休暇日数 |
| 欠勤日数 | 欠勤の日数 |

#### F-21 月次集計（部署別・全体）

- 部署ごと・全体の集計表を表示する（社員×項目のマトリクス）

#### F-22 集計結果のCSV出力

- 月次集計結果を CSV 形式で出力する
- 文字コードは **UTF-8 with BOM**（Excelで文字化けしないように）を基本とする

### 5.7 ダッシュボード

#### F-23 ホーム画面

- ログイン後のホーム画面に以下を表示する
  - 当日の打刻状況（出勤済み/未打刻、現在時刻）
  - 打刻ボタン（出勤・退勤・休憩）
  - 当月の勤怠サマリ（出勤日数・実働時間・残業時間）

## 6. 非機能要件

### 6.1 セキュリティ要件

| 要件 | 内容 |
|------|------|
| パスワード保存 | bcrypt（コスト12）でハッシュ化して保存する。平文保存・可逆暗号化は禁止 |
| セッション管理 | サーバーサイドでセッションを管理し、Cookie に HttpOnly・Secure 属性を付与する |
| SQL インジェクション対策 | ORM（SQLAlchemy）の利用を基本とし、生SQLは原則使用しない |
| XSS 対策 | テンプレートで自動エスケープ（Jinja2 はデフォルトで有効）を利用する |
| CSRF 対策 | フォーム送信には CSRF トークンを付与する |
| 認可 | ロールに応じたアクセス制御を行う（一般社員は他者のデータにアクセス不可） |
| 監査 | 勤怠データの修正履歴を必ず残す |

### 6.2 性能・可用性要件

| 要件 | 内容 |
|------|------|
| 対象規模 | 社員 100 名規模（同時アクセス数: 数十）を想定 |
| 応答時間 | 画面表示・操作は 2 秒以内を目標 |
| 稼働時間 | 業務時間中（平日 9:00〜18:00）の可用性を確保 |
| バックアップ | SQLite データベースのバックアップ手順を用意する（本番は想定しない学習用途） |

### 6.3 保守性・運用要件

- コードには丁寧なコメントを付与し、設計ドキュメントと整合させる
- 画面・機能・DB スキーマの変更は設計書を更新してから実施する
- ログはアプリケーションログとアクセスログを分けて出力する

### 6.4 その他

- 画面・メッセージは**日本語**を基本とする
- タイムゾーンは JST（日本標準時）を想定する

## 8. システム構成・アーキテクチャ

### 8.1 技術スタック

| レイヤ | 技術 | 選定理由 |
|--------|------|----------|
| 言語 | Python 3.13 | 読みやすく学習コストが低い。Web・データ処理のエコシステムが豊富 |
| Web フレームワーク | FastAPI | 型ヒントベースで明快。自動 API ドキュメント。実務での採用が増加 |
| テンプレート | Jinja2 | FastAPI と標準連携。サーバーサイドレンダリングで学習しやすい |
| ORM | SQLAlchemy 2.x | Python の標準的 ORM。DB をオブジェクトとして扱える |
| マイグレーション | Alembic | スキーマ変更をバージョン管理する実務標準の仕組み |
| DB | SQLite | ファイルベースで環境構築が容易。学習用途に最適 |
| 認証 | セッション + bcrypt | サーバーサイドテンプレート構成ではセッション方式が素直 |
| パスワードハッシュ | pwdlib[bcrypt] | passlib 後継・FastAPI 公式推奨のメンテナンス中ライブラリ |

### 8.2 アーキテクチャ方針

- **レイヤ構造**: `ルーター(コントローラ)` → `サービス` → `リポジトリ(DBアクセス)` → `モデル` のレイヤ分割とする
- **トランザクション**: DB 更新を伴う処理（打刻・修正）はトランザクション内で実行し、失敗時はロールバックする
- **ビジネスルール**: 労働時間の計算ロジックはサービス層に集約し、テスト可能にする

## 12. 制約条件・前提

- **対象規模**: 社員 100 名程度の小規模組織を前提とする
- **時間帯**: 日勤（9:00〜18:00）を基本とし、夜勤は「出勤日基準」で扱う
- **タイムゾーン**: JST 固定
- **運用形態**: 学習用・テスト用のため、堅牢な本番運用（冗長化・監視）は対象外
- **法律対応**: 労働基準法への完全準拠（法定休日・36協定・割増率計算の正確性）は本要件の範囲外とし、実装で対応可能な範囲で行う
- **データ**: 本リポジトリはパブリックのため、動作確認には**ダミーデータ**を使用する
