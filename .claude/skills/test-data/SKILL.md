# テストデータの生成

このプロジェクトはパブリックリポジトリのため、**実データは使わずダミーデータのみ**を使用する。
ダミーデータはスクリプト（`app/seed.py`）で生成し、SQLite ファイル（`data/*.db`）はコミットしない。

## 生成手順

```bash
# シードデータの投入（DB作成 + マスタ + 社員 + 打刻データ）
.venv/bin/python -m app.seed
```

## 生成されるデータの内容

| データ | 内容 |
|--------|------|
| 部署マスタ | 複数部署（例: 総務部 / 営業部 / 開発部） |
| 勤務体系 | 標準8時間勤務など |
| 休暇種別 | 年次有給休暇 / 慶弔休暇 / 欠勤 など |
| 社員 | 管理者 1名 + 一般社員 5名程度（ダミー氏名） |
| 打刻データ | 直近1〜2ヶ月分のダミー打刻・日別勤怠 |

## ダミー社員のルール

- 社員番号・氏名は明らかにダミーであること（例: `E0001` / `テスト 太郎`）
- パスワードは全員共通のダミー値（例: `password123`）で良いが、**ハッシュ化して保存**すること
- 実在の人名・実在企業のデータを使わないこと

## 注意点

- `data/` ディレクトリ配下の DB ファイルは git 管理対象外（.gitignore で除外）
- シードを実行し直すと既存データは上書きされる（全件削除 → 再投入）
- テストコードで毎回同じ状態にしたい場合は、シード後に DB ファイルをコピーして使い回す
